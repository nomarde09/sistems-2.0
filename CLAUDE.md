# Правила работы с проектом

- Пользователь не программист: весь код, установку, запуск, тесты и проверку в браузере делает Claude. Не давать инструкций вида «создай файл» или «запусти команду».
- Общение по-русски, простыми словами.
- Коммитить и пушить только по просьбе пользователя.
- Не коммитить секреты (`.env`, ключи, базу данных, папку `data/` с копиями).
- Не показывать пароли из `.env` в чате. Временные пароли сотрудников показывать, только когда пользователь сам попросил их выдать.
- После изменений гонять тесты: `.venv\Scripts\python.exe -m unittest discover -s tests -v`. Все должны проходить.
- Все POST-формы содержат поле `csrf` (`<input type="hidden" name="csrf" value="{{ csrf_token() }}">`).
- Пароли сотрудников и техраздела хранятся только как хеши argon2 (`hash_password` / `check_hash`). Пароли в открытом виде не хранить нигде: ни в `.env`, ни в базе, ни в логе.
- Остальные секреты (csrf) сравнивать только через `hmac.compare_digest` по байтам (`secrets_equal`).
- SQL: значения только через `?`. В f-строки SQL можно подставлять только имена столбцов из кода (это проверяет `tests/test_audit.py`).
- Всё, что пришло из запроса, писать в лог только через `safe_for_log()`. Пароли, тексты заявок и строки поиска в лог не попадают.
- Никаких встроенных скриптов (`<script>` без `src`, `onclick=`) и стилей `style="..."`, внешних CDN и шрифтов: строгая политика CSP их запрещает. Скрипты — файлами в `static/`.
- Каждая новая страница — с `@login_required(...)` и нужными ролями; бригаде — только её заявки.
- Загрузки файлов сейчас нет. Если появится: проверять тип по содержимому, ограничивать размер, давать случайное имя, хранить в `data/uploads` (вне `static/`) и отдавать только через проверку прав.
- Ключи `REQUEST_TYPES` и `EQUIPMENT` не переименовывать: по ним считается статистика и они лежат в базе.
- Режим отладки только локально (`python app.py --otladka`), на хостинге — `wsgi.py`.
- После правки `.env` перезапускать сайт.
